# Система мониторинга конкурентов, новостей и упоминаний

Автоматизированная система для отслеживания изменений на сайтах конкурентов, мониторинга отраслевых новостей и поиска упоминаний компании в интернете с использованием LLM для анализа и категоризации.

## 🎯 Основные возможности

### Мониторинг конкурентов
- ✅ Автоматическое сканирование веб-сайтов конкурентов
- ✅ Мониторинг Telegram-каналов конкурентов
- ✅ Обнаружение и категоризация изменений через LLM
- ✅ Категории: Продукты, Цены, Услуги, Новости, Акции, Прочее
- ✅ Отслеживание здоровья конкурентов и URL (отсчёт ошибок)
- ✅ Генерация PDF-отчетов
- ✅ Группировка конкурентов
- ✅ Кэширование контента для быстрого поиска изменений

### Мониторинг отраслевых новостей
- ✅ Сканирование новостных Telegram-каналов
- ✅ Парсинг новостных веб-сайтов (с поддержкой CSS-селекторов)
- ✅ Автоматическая классификация по категориям (LLM + уверенность)
- ✅ Дедупликация контента по хешам
- ✅ Генерация новостных дайджестов со статистикой
- ✅ Архивирование истории сканирований

### Мониторинг упоминаний
- ✅ Поиск упоминаний бренда через Yandex Search API
- ✅ Мониторинг Telegram-каналов на предмет упоминаний
- ✅ Парсинг веб-порталов по CSS-селекторам
- ✅ Анализ тональности (позитивная / нейтральная / негативная) через LLM
- ✅ Дедупликация по URL
- ✅ Настройка поисковых терминов и источников через Web App

### Web-интерфейс
- ✅ Telegram Web App для удобного доступа
- ✅ Единая лента изменений и новостей (infinite scroll)
- ✅ Экран упоминаний компании с фильтрами по источнику и тональности
- ✅ История сканирований конкурентов и новостей
- ✅ Управление конкурентами и источниками
- ✅ Фильтрация по группам, категориям, источникам, датам
- ✅ Настройки категорий, каналов, поисковых терминов и источников упоминаний

### Управление и безопасность
- ✅ Система ролей (admin/editor/viewer)
- ✅ Row-Level Security (RLS) в Supabase
- ✅ Управление расписанием сканирования
- ✅ История запросов на сканирование через Telegram Bot

## 🏗️ Архитектура

Система состоит из следующих компонентов:

1. **Python Backend** - скрипты для сканирования и обработки
   - `monitor.py` - мониторинг конкурентов (веб-сайты и Telegram)
   - `news_monitor.py` - мониторинг отраслевых новостей
   - `mentions_monitor.py` - мониторинг упоминаний компании

2. **Supabase** - PostgreSQL база данных + Auth
   - Row-Level Security для защиты данных
   - Управление ролями и доступом

3. **React Web App** - пользовательский интерфейс (Vite)
   - Телеграм Web App
   - Экраны: FeedScreen, ScansScreen, CompetitorsScreen, MentionsScreen, SettingsScreen

4. **Telegram Bot** - интерфейс управления и уведомления
   - Управление сканированиями
   - Отправка отчетов и дайджестов

5. **GitHub Actions** - автоматизация по расписанию
   - Отслеживание запросов на сканирование
   - Логирование результатов

## 🚀 Быстрый старт

### Требования

- Python 3.11+
- Node.js 18+
- Supabase проект
- Telegram Bot Token
- OpenAI/Groq API ключ

### Установка зависимостей

```bash
# Backend
pip install -r requirements.txt
playwright install chromium

# Frontend
cd webapp
npm install
```

### Настройка переменных окружения

Создайте файл `.env` в корне проекта:

```bash
SUPABASE_URL=https://xxx.supabase.co
SUPABASE_KEY=your_supabase_service_key
TELEGRAM_BOT_TOKEN=your_bot_token
TELEGRAM_CHAT_ID=your_chat_id
GROQ_API_KEY=your_groq_api_key
YANDEX_SEARCH_API_KEY=your_yandex_api_key
YANDEX_SEARCH_FOLDER_ID=your_folder_id
```

Для фронтенда создайте `webapp/.env`:

```bash
VITE_SUPABASE_URL=https://xxx.supabase.co
VITE_SUPABASE_ANON_KEY=your_supabase_anon_key
```

### Запуск

```bash
# Мониторинг конкурентов
python monitor.py

# Мониторинг новостей
python news_monitor.py

# Мониторинг упоминаний
python mentions_monitor.py

# Web-интерфейс (development)
cd webapp
npm run dev
```

## 📅 Автоматизация

Система автоматически запускается по расписанию через GitHub Actions:

- **Конкуренты**: каждый четверг в 18:00 МСК
- **Новости**: каждую пятницу в 9:00 МСК
- **Упоминания**: каждый понедельник в 9:00 МСК

## 🗄️ Структура базы данных

### Основные таблицы

**Конкуренты и мониторинг:**
- `competitors` - список конкурентов
- `competitor_urls` - URL для мониторинга (веб-сайты и Telegram каналы)
- `competitor_content` - кэш контента конкурентов
- `competitor_groups` - группировка конкурентов
- `changes` - обнаруженные изменения
- `competitor_tg_posts` - посты из Telegram-каналов
- `summary_reports` - сводные отчеты
- `scan_results` - детальные результаты сканирования

**Здоровье и контроль:**
- `competitor_health` - отслеживание последовательных ошибок
- `url_health` - здоровье отдельных URL
- `scan_problems` - проблемы и ошибки при сканировании
- `bot_settings` - управление расписанием сканирования
- `scan_requests` - история запросов на сканирование

**Новости:**
- `news_channels` - источники новостей (Telegram + веб-сайты)
- `news_posts` - новостные посты
- `news_categories` - категории новостей
- `news_post_categories` - классификация постов с уверенностью
- `news_digests` - дайджесты (статистика сканирований)
- `news_digest_posts` - связь дайджестов с постами

**Упоминания:**
- `mention_search_terms` - поисковые термины (названия бренда/компании)
- `mention_sources` - источники для мониторинга (TG-каналы, веб-порталы)
- `mention_scans` - история запусков мониторинга упоминаний
- `mentions` - найденные упоминания (уникальные по URL)

**Управление доступом:**
- `users` - пользователи системы (роли: admin/editor/viewer)
- `groups` - группы конкурентов

См. [DATABASE_SCHEMA.md](docs/DATABASE_SCHEMA.md) для полной схемы.

## 🔄 Процесс работы

### Мониторинг новостей

1. **Сканирование** - сбор новых постов из источников
2. **Обработка LLM** - извлечение заголовков, summary, категоризация
3. **Дайджест** - создание статистики сканирования в `news_digests`
4. **Уведомления** - отправка PDF и сводки в Telegram

### Мониторинг конкурентов

1. **Сканирование** - проверка веб-сайтов и Telegram каналов
2. **Определение изменений** - сравнение с предыдущим состоянием
3. **Категоризация** - классификация изменений через LLM
4. **Отчеты** - генерация PDF и уведомления

## 📊 Статистика и отчеты

Система сохраняет подробную статистику каждого сканирования:

- Количество просканированных источников
- Количество найденных изменений/новостей
- Статистика по категориям
- Ошибки и проблемы при сканировании
- PDF-отчеты с визуализацией

## 🔒 Безопасность

- **Row Level Security (RLS)** в Supabase для защиты данных
- **Аутентификация** через Telegram Web App (`initData`)
- **Ролевая модель:** admin (полный доступ), editor (редактирование), viewer (только чтение)
- **Защищенное хранение:** API ключи в переменных окружения
- **Изоляция пользователей:** каждый видит только свои данные
