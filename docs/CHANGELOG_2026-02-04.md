# Changelog - Исправление системы дайджестов новостей

## Дата: 4 февраля 2026

### Проблема
- Таблица `news_digests` была пустой
- На странице "Сканирования" → "Новости" не отображались данные
- Посты сохранялись в `news_posts`, но статистика сканирований не создавалась

### Причина
1. В коде Python использовались неправильные поля БД (`total_posts`, `total_channels` вместо `posts_count`)
2. Дайджест создавался только если были посты (внутри `if digest_posts:`)
3. Функция `getNewsDigests` на фронтенде не подсчитывала количество каналов

### Исправления

#### Backend (news_monitor.py)

1. **Исправлены поля для сохранения дайджеста**
   - Использован `posts_count` вместо `total_posts` (согласно схеме БД)
   - Добавлено поле `categories_summary` для сводки по категориям
   - Убрано несуществующее поле `total_channels`

2. **Дайджест теперь сохраняется всегда**
   - Даже если нет постов, создается запись в `news_digests` со статистикой сканирования
   - Это позволяет отслеживать все запуски мониторинга

3. **Улучшено логирование**
   - Добавлены сообщения об успешном сохранении дайджеста с ID
   - Переименована "ФАЗА 3" в "ГЕНЕРАЦИЯ ДАЙДЖЕСТА И СОХРАНЕНИЕ СТАТИСТИКИ"

#### Frontend (webapp/src/services/news.js)

1. **Функция `getNewsDigests`**
   - Добавлен подсчет уникальных каналов через `news_digest_posts`
   - Добавлено вычисление `period_days` из `period_start` и `period_end`
   - Маппинг `posts_count` → `total_posts` для совместимости с UI
   - Добавлено поле `total_channels` (вычисляется на лету)

2. **Функция `getNewsDigestDetails`**
   - Исправлена логика получения постов через промежуточную таблицу `news_digest_posts`
   - Убран несуществующий фильтр `digest_id` из `news_posts`
   - Используется правильная связь: `news_digests` → `news_digest_posts` → `news_posts`

#### Frontend (webapp/src/components/ui/ScanCard.jsx)

1. **Отображение дайджестов**
   - Используется `digest_date` вместо `created_at` для заголовка
   - Добавлен fallback `scan.total_posts || scan.posts_count` для совместимости
   - Улучшена обработка отсутствующих полей

#### Frontend (webapp/src/components/screens/ScansScreen.jsx)

1. **Улучшены сообщения о пустом состоянии**
   - Разные сообщения для конкурентов и новостей
   - Добавлена иконка и подсказки что делать
   - Убран отладочный код

### Структура изменений в БД

Теперь при каждом сканировании создается:

```
news_digests
├─ id (serial)
├─ digest_date (дата сканирования)
├─ period_start (начало периода)
├─ period_end (конец периода)
├─ posts_count (количество постов)
├─ categories_summary (JSONB: сводка по категориям)
├─ pdf_url (опционально)
└─ created_at

news_digest_posts (связь с постами)
├─ digest_id → news_digests.id
├─ post_id → news_posts.id
└─ rank_in_category
```

### Как использовать

1. **Создать первый дайджест:**
   ```bash
   python news_monitor.py
   ```

2. **Проверить в Web App:**
   - Открыть "Сканирования"
   - Переключиться на "Новости"
   - Должна появиться карточка с дайджестом

3. **Автоматические дайджесты:**
   - Создаются каждый понедельник в 15:00 МСК
   - Через GitHub Actions

### Тестирование

Для проверки работоспособности:

```sql
-- Проверить количество дайджестов
SELECT COUNT(*) FROM news_digests;

-- Посмотреть последний дайджест
SELECT * FROM news_digests ORDER BY created_at DESC LIMIT 1;

-- Посмотреть посты дайджеста
SELECT p.*, dp.rank_in_category
FROM news_posts p
JOIN news_digest_posts dp ON p.id = dp.post_id
WHERE dp.digest_id = 1;
```
