# Инструкция по созданию первых дайджестов новостей

## Проблема

Таблица `news_digests` пустая, поэтому на странице "Сканирования" → "Новости" ничего не отображается.

## Решение

Запустите скрипт `news_monitor.py` для создания первого дайджеста.

## Шаги

### 1. Убедитесь, что есть активные источники новостей

Проверьте в БД (или через Web App → Настройки):
- В таблице `news_channels` должны быть активные каналы (`is_active = true`)
- У каналов должен быть указан `source_type` (telegram/website)

### 2. Настройте переменные окружения

Создайте `.env` файл в корне проекта (если еще не создан):

```bash
SUPABASE_URL=https://xxx.supabase.co
SUPABASE_KEY=your_supabase_service_key
TELEGRAM_BOT_TOKEN=your_bot_token
TELEGRAM_CHAT_ID=your_chat_id
GROQ_API_KEY=your_groq_api_key

# Telegram App API (для Telethon)
TELEGRAM_API_ID=your_api_id
TELEGRAM_API_HASH=your_api_hash
```

### 3. Установите зависимости

```bash
pip install -r requirements.txt
playwright install chromium
```

### 4. Запустите мониторинг новостей

```bash
python news_monitor.py
```

### 5. Что произойдет

Скрипт выполнит 3 фазы:

**Фаза 1: Сканирование**
- Соберет новые посты из Telegram-каналов и веб-сайтов
- Сохранит их в `news_posts` с `is_processed=false`

**Фаза 2: LLM-обработка**
- Обработает новые посты через LLM
- Извлечет заголовки и саммари
- Классифицирует по категориям
- Обновит `is_processed=true`

**Фаза 3: Создание дайджеста**
- Создаст запись в `news_digests` со статистикой:
  - `digest_date` - дата сканирования
  - `period_start/period_end` - период охвата (обычно 7 дней)
  - `posts_count` - количество постов
  - `categories_summary` - сводка по категориям
- Свяжет посты через `news_digest_posts`
- Сгенерирует PDF (если есть посты)
- Отправит уведомление в Telegram

### 6. Проверьте результат

После завершения:
1. Откройте Web App
2. Перейдите на "Сканирования" → "Новости"
3. Должна появиться карточка с дайджестом

## Что делать если нет постов

Если в логе видите "Постов для дайджеста: 0", значит:

1. **Нет активных источников** - добавьте каналы/сайты в `news_channels`
2. **Период слишком короткий** - скрипт берет последние 7 дней
3. **Все посты уже обработаны** - дайджест все равно создастся, но будет пустым

## Изменение периода сканирования

По умолчанию скрипт берет последние 7 дней. Чтобы изменить:

```python
# В news_monitor.py, найдите строки:
period_end = datetime.now(UTC)
period_start = period_end - timedelta(days=7)  # <- измените на нужное количество дней
```

## Автоматизация

После первого запуска, дайджесты будут создаваться автоматически каждый понедельник в 15:00 МСК через GitHub Actions.

## Структура данных

После создания дайджеста в БД будут записи:

```sql
-- Дайджест со статистикой
SELECT * FROM news_digests ORDER BY created_at DESC LIMIT 1;

-- Посты дайджеста
SELECT * FROM news_digest_posts WHERE digest_id = <digest_id>;

-- Связанные новостные посты
SELECT p.* 
FROM news_posts p
JOIN news_digest_posts dp ON p.id = dp.post_id
WHERE dp.digest_id = <digest_id>;
```

## Частые проблемы

### Ошибка "supabase_url is required"
- Проверьте, что `.env` файл существует
- Проверьте, что переменные загружаются: `python -c "import os; print(os.getenv('SUPABASE_URL'))"`

### Ошибка при доступе к Telegram
- Убедитесь, что `TELEGRAM_API_ID` и `TELEGRAM_API_HASH` правильные
- При первом запуске нужно авторизоваться (введите номер телефона и код)

### LLM ошибки
- Проверьте баланс API ключа
- Проверьте лимиты запросов (в коде есть семафор на 5 одновременных)
